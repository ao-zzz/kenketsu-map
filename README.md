# 献血のお願いマップ（非公式）

各地の赤十字血液センターが出している「献血状況」（血液型ごとの献血へのお願い）を、1日1回読み取り、全国の地図にまとめた非公式のサイトです。

**https://kenketsu-map.pages.dev/**

> 日本赤十字社・各血液センターとは関係のない、個人が運営する非公式のページです。最新の情報は、各血液センターのページでご確認ください。

## なぜ作ったか

献血状況は、全国47か所の血液センターが、それぞれのページに出しています（同じブロックの中は同じ表示なので、中身は7種類です）。自分の県のことだけなら、その県の血液センターのページで分かります。

ただ、SNS で「血液が足りない」と話題になったとき、それが全国の話なのか、自分の地域もなのか、何型なのかを1枚で見られる場所は、探した範囲では見つかりませんでした。

そこで、7ブロックの表示を血液型ごとに1枚の地図にまとめ、見た人を各血液センターのページと献血の予約（ラブラッド）へ案内するサイトにしました。

3. どちらも難しい場合は、公開しないこと

お返事では、日本赤十字社のサイトで作る予定は今はないこと、個人のサイトに公式の許可や承認を出すことはできないことをご説明いただきました。そのうえで、日本赤十字社の「[リンク・著作権について](https://www.jrc.or.jp/rule/)」の範囲で、個人の責任において公開・運営していただく形であればとのお返事をいただき、公開にあたって気をつける点として、次のことをご指摘いただきました。

- 患者さんに無用な心配をおかけしない表示にすること
- 非公式のページであることを明記すること
- 赤十字マークやロゴを使わないこと
- 最新の情報は、各血液センターのページへご案内すること
- 日本赤十字社から修正や掲載の取りやめをお願いすることがあること

いただいたご指摘をすべて反映して作り直し、公開しました。公開後には、ページの住所と、それぞれのご指摘をどう反映したかをお知らせしています。お知らせに対して、日本赤十字社から、ご指摘を反映したことと、そのご報告へのお礼のご連絡をいただきました。

公式の許可や承認を受けたものではないため、このサイトの内容の責任は運営者にあります。

## 見せ方で気をつけたこと

このサイトは、献血する人だけでなく、輸血を受ける患者さんやご家族も目にする可能性があります。日本赤十字社からのご指摘をふまえ、患者さんに無用な心配をかけないよう、次のようにしています。

- **全国の地図では、強さの違いを見せません。** 「献血のお願いあり」「確保できている」の2つだけで表します。「非常に困ってます」などの血液センターの言葉は、見る人が自分の地域を選んだときと、都道府県ごとのページの中だけに出します
- **最初の画面では、どの地域も選んでいません**
- **いちばん上に「輸血を受ける方・ご家族へ」の一文を置いています。** 在庫の数字ではなく献血へのお願いのメッセージであること、ご自身の輸血については主治医に相談してほしいことを書いています
- 「不足」「危機」などの言葉で不安をあおる見出し、点滅、警告のマークは使いません。「血液が足りない」と検索した人に落ち着いて確かめてもらうため、その言葉はページ下部の説明欄でだけ使っています
- 不安で終わらせず、「あなたにできること」として献血の予約への道を出しています

最初の版は、地図を「非常に困ってます」の赤で塗り分ける見せ方でした。そこから見出し・色・言葉を何度か作り直し、作り直す前と後の画面を家族に見てもらって確かめました。

## しくみ

```
毎朝 7:00（GitHub Actions）
  ① 読む      7ブロックの血液センターのページを、1.5秒ずつあけて1回ずつ読む
  ② 確かめる  決まった形か（7ブロック × 3種類 × 4つの血液型、値は 0・25・50・100 だけ）
              不自然な変化（7ブロック全部が一度に変わる など）は自動で出さず、止める
  ③ 記録する  data/latest.json と data/history/日付.json をリポジトリに残す
  ④ 配る      dist/（HTML・CSS・JS・data.json）を Cloudflare Pages へ
              ②で止まった日は「値を出さない画面」を配ったうえで、実行を失敗にしてメールで知らせる
```

サーバーで動くプログラム、ログイン、書き込み、データベースはありません。公開しているのはファイルだけです。

## セキュリティ

「何が起きたら困るか」から決めごとを作り、決めごと1つずつに確かめ方（テストや手順）をつけました。

| 困ること | 決めごと | 確かめ方 |
|---|---|---|
| 偽の呼びかけが出る（改ざん） | 受け付ける値は4段階と決まった形だけ。形が違えば古い値も新しい値も出さずに止める | 75、-1、`"abc"`、項目の不足などを入れたテストで止まるか（`tests/reader.test.mjs`） |
| 読み取った文字にスクリプトが紛れる（XSS） | 日付の文字は長さと文字の種類を絞る。画面には `textContent` だけで入れ、`innerHTML` を使わない。配る前に作る HTML は全部エスケープする | 日付に `<script>alert(1)</script>` と `<img src=x onerror=…>` を入れたテストと、確かめ用の画面（`npm run check:script`） |
| 元のページが乗っ取られる | 7ブロックが一度に変わったら自動では出さず、人が元のページを見て確かめてから出す。前の日が止まっていても、最後にうまく読めた回と比べる | テスト |
| よそのサーバーに巻き込まれる | 外部のスクリプト、フォント、解析のタグを読み込まない。フォントも自分で配る | ブラウザの開発者ツールで、外への読み込みが0か |
| スクリプトが紛れても動かされる | CSP で自分のファイルだけを許可（`script-src 'self'; style-src 'self'`）。ページの中に直接書いたスクリプトと見た目の指定をなくした。よそのサイトの枠の中に表示させない | 本物の住所で、ヘッダーが付いているか（`site/_headers`） |
| 古い値を出し続ける | 毎朝の仕組みが動かない日が続いても、地図は2日より古い値を出さない | 時計をずらしてブラウザで確かめた |
| 配る鍵が漏れる | Cloudflare の鍵は GitHub の Secrets に置き、権限は「このサイト専用のアカウントの Pages」だけ、期限は1年。毎朝の仕組みは「毎朝の時刻」と「手で押したとき」だけ動き、プルリクエストからは動かない | 鍵の権限の画面、Actions の記録 |
| 部品が書きかえられる | サイトとテストは外の部品を使わない（Node の標準だけ）。GitHub Actions の部品はコミットの番号で固定。配る道具（wrangler）は出て2週間以上たった版を、`package-lock.json` で中身まで固定し、インストール時のスクリプトを動かさない | `deploy/package-lock.json`、`.github/workflows/daily.yml` |
| 血液センターのサーバーに負担をかける | 読むのは決まった7つの住所だけ、1日1回、1.5秒ずつあける。転送は追わない | `reader/run.mjs` |

**確かめていないこと**：パソコンの WebKit では、都道府県を選ぶ欄（`<select>`）を描くときに、ブラウザ自身が CSP の警告を出します（ページの書き方ではなく、欄は動きます）。都道府県のページは JavaScript を使わないため、「2日より古い値を出さない」守りは効きません（読み取った日時を表示し、失敗のメールで気づく形です）。

## 技術の選び方

| 選んだもの | 理由 |
|---|---|
| 静的なサイト（ファイルだけ） | 攻撃される入口を作らない。表示は1日1回変わるだけなので、サーバーで動かす必要がない |
| GitHub Actions で読み取り | 読み取りと配信を分けられる。読んだ値が毎日リポジトリの履歴に残り、「いつ何を出したか」を後から確かめられる |
| Cloudflare Pages | `_headers` で CSP などを決められる。静的なファイルは無料 |
| 自分のドメインを買わない | やめたあとも毎年払い続ける負担と、期限切れで住所を他人に取られる心配をなくす |
| 外の部品を使わない（Node の標準だけ） | 部品の乗っ取りの影響を受けない。テストも `node --test` |
| フォントを自分で配る（使う文字だけ） | 外を読み込まないため。日本語のフォントは重いので、ページで使う文字を含む分だけに絞った（約1.6MB） |

## フォルダ

```
reader/      ① 読む・② 確かめる（parse.mjs、validate.mjs、run.mjs）
data/        読んだ値（latest.json）と毎日の記録（history/）
site/        画面（index.html、app.js、map.js、style.css、fonts/、_headers）
build/       配るファイルを dist/ に作る。47の都道府県のページ、sitemap.xml、404 も作る
tests/       テストと、確かめ用の画面のデータ（screens/）
tools/       手元で見るサーバー（_headers をつける）、フォントを取る、アイコンを作る
deploy/      配る道具（wrangler）だけ。版と中身を固定
.github/     毎朝の仕組み（daily.yml）
site.config.json  公開の住所、検索に載せるか、運営者と連絡先
```

## 手元で動かす

Node.js 22 以上。外の部品のインストールは要りません。

```sh
npm test                 # テスト
npm run preview          # dist/ を作って http://localhost:8730 で見る（_headers もつける）
npm run check:script     # 日付にスクリプトを入れた画面を http://localhost:8731 で見る
npm run check:bad-value  # 4段階にない値を入れた画面
npm run check:stopped    # 読み取りが止まった日の画面
npm run read             # 本物の7ページを1回読む（必要なときだけ）
```
